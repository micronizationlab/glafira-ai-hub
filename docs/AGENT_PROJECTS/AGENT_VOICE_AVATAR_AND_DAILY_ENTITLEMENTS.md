# Общая спецификация: голос, аватар и адресные тарифные расширения

Статус: проектирование; платежи и автоматические обновления не реализованы и не разрешены к запуску.

## 1. Индивидуальность профиля

Каждый агент имеет собственные:
- стабильный ID и отображаемое имя;
- визуальный аватар и краткую анимацию (если поддерживается платформой);
- голосовой профиль: тембр, скорость, манера речи, произношение и эмоциональная выразительность;
- текстовое и аудиопредставление;
- тарифный профиль и фактически доступные возможности.

Голоса должны быть оригинальными или лицензированными. Нельзя копировать голос реального человека без соответствующих прав и согласия. При смене тарифа агент может получать другой голосовой стиль и аватар, если это явно указано в матрице тарифа. Нельзя выдавать рекламируемые функции за доступные до проверки entitlement.

## 2. Профиль GLAFIRA

У GLAFIRA собственный постоянный голос и профиль звучания. Пользователь выбирает аватар GLAFIRA в настройках профиля из доступного каталога. Выбор синхронизируется между устройствами пользователя, если включена синхронизация профиля. Голос можно выбирать из разрешённых вариантов; платформа должна иметь понятные настройки громкости, скорости, тестового прослушивания и отключения озвучивания.

Аватар GLAFIRA не должен неожиданно меняться вследствие покупки тарифа агента. Пользовательский выбор сохраняется, пока сам пользователь его не изменит.

## 3. Матрица тарифов

Для каждого агента проект хранит версионируемую матрицу:
- тариф ID и название;
- суточная стоимость и валюта учёта;
- включённые capability IDs;
- голосовой preset ID;
- avatar/theme ID;
- лимиты использования;
- требуемые модели/инструменты и их стоимость;
- ограничения и предупреждения;
- дата начала и окончания действия;
- правила grace period, возврата и отключения.

Бесплатный базовый уровень сохраняется. Тариф агента не должен автоматически повышать глобальный тариф GLAFIRA или разрешать платный API. Платные upstream-модели требуют отдельного явного разрешения и лимита расходов.

## 4. Покупка прямо из чата агента

1. В чате пользователь нажимает «Изменить тариф» или выбирает расширение.
2. GLAFIRA Core запрашивает у Token/Wаllet сформировать платёжное намерение.
3. Кошелёк открывается по проверенной активной ссылке/deep link. В ней заранее указаны подписанные идентификаторы получателя/проекта/агента/тарифа, уникальный invoice ID, цена за сутки и сумма за одни сутки.
4. Единственное поле, которое пользователь должен менять, — количество суток. Значение по умолчанию: 1. Итоговая сумма пересчитывается автоматически как цена суток × число суток; ограничения максимального срока и минимальной суммы задаются тарифом.
5. Перед подтверждением кошелёк показывает получателя, агента, тариф, число суток, цену за сутки, итог, комиссию (если есть) и срок действия счёта.
6. Пользователь явно подтверждает перевод. Возврат из кошелька сам по себе не считается оплатой.
7. Token проверяет транзакцию в авторитетном ledger, подтверждения/финальность, валюту, сумму, invoice ID, уникальность и отсутствие повторного зачисления.
8. Только подтверждённая оплата создаёт событие `PaymentSettled` и entitlement. Никаких обновлений на основании скриншота, нажатия кнопки или клиентского callback без серверной/ledger проверки.

Если платёжный протокол/кошелёк не поддерживает безопасную передачу подписанных параметров, не открывать оплату автоматически: показать защищённый экран подтверждения внутри приложения.

## 5. Адресное обновление от GLAFIRA Mother

После подтверждения оплаты Mother формирует короткое персональное обновление:
- адресат: account ID + installation/device ID (или утверждённая группа устройств);
- agent ID, тариф ID и набор capability IDs;
- срок действия в секундах/UTC timestamps, рассчитанный из оплаченных суток;
- invoice ID и ledger transaction reference;
- package/manifest version, минимальная совместимая версия приложения;
- хеш содержимого и цифровая подпись;
- правила отката и срок действия самого предложения обновления.

Клиент видит уведомление и кнопку «Обновить». По нажатию приложение загружает только адресованное ему расширение, проверяет подпись, хеш, получателя, совместимость и разрешения, затем автоматически устанавливает пакет без ручной распаковки. До установки показывается краткое описание изменений и срока доступа. Если требуется перезапуск, пользователь получает понятное уведомление.

## 6. Что именно устанавливается

Предпочтительный формат — подписанный декларативный пакет: entitlement + capability manifest + голосовой/визуальный preset + версионированный контент и конфигурация. Произвольный исполняемый код не должен устанавливаться как обычное обновление тарифа. Если в будущем действительно требуется исполняемый модуль, он проходит отдельный review, sandbox, подпись, разрешения, SBOM, тесты и явное согласование владельца.

## 7. Срок, истечение и офлайн

- Срок считается от зафиксированного момента активации либо от момента оплаты — правило должно быть одинаково показано до оплаты.
- Время хранится в UTC; интерфейс показывает локальное время пользователя и точную дату окончания.
- Продление создаёт отдельную ledger запись и продлевает entitlement идемпотентно.
- Повторная доставка одного обновления не продлевает срок и не создаёт повторную оплату.
- При истечении тарифа платные capability выключаются, голос/аватар возвращаются к бесплатному уровню, история чата и пользовательские данные сохраняются.
- Офлайн-проверка использует подписанный ограниченный по времени entitlement и защищённые часы/счётчик, насколько это поддерживает платформа. Нельзя обещать абсолютную защиту от перевода часов на устройстве; нужен период повторной онлайн-проверки и безопасный grace policy.
- Возврат, спор, отмена, сбой сервиса и восстановление устройства требуют отдельной политики.

## 8. Безопасность и контроль

- Ссылка не содержит секретный ключ и не позволяет менять получателя или тариф.
- Invoice ID уникален, короткоживущий, подписан и связан с конкретным пользователем/проектом.
- Проверка оплаты выполняется только в Token/Core; клиент не может сам назначить себе тариф.
- Подпись пакета проверяется до установки; downgrade и replay блокируются.
- Доступ проверяется в Core при каждом привилегированном действии, а не только скрытием кнопок.
- Журналируется кто, когда, что оплатил, какой пакет получил, на каких устройствах и когда срок истёк; хранить минимум необходимых данных.
- Обновление можно отозвать при компрометации; откат не удаляет пользовательские данные.
- При недоступности Token/сети не выдавать платный entitlement по предположению.

## 9. Необходимые тесты

Invoice tampering, неверный получатель, повторный webhook, duplicate transaction, underpayment, wrong asset/currency, expiry, refund, clock rollback, offline expiry, wrong device, invalid signature, package tampering, downgrade, replay, interrupted install, rollback, revoked entitlement, app-version mismatch и multi-device sync.
