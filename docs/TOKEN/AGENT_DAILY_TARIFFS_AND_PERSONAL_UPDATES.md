# Token: посуточные тарифы агентов и адресные персональные обновления

Статус: архитектурное предложение по требованию владельца от 2026-11-23. Не является разрешением запускать платежи, менять цены, выпускать токены или включать коммерческий режим.

## 1. Роль Token

Token — самостоятельный проект экономики, кошелька, платежного намерения, авторитетного ledger, подтверждения транзакций и учёта тарифных прав. GLAFIRA Mother/Core координирует запрос и выдачу расширения, но не подменяет финансовый ledger.

## 2. Посуточная единица

Каждый тариф агента имеет цену за сутки в утверждённой единице учёта. В чате агента пользователь нажимает «Изменить тариф». Кошелёк открывается с готовыми параметрами:
- invoice ID;
- account/user ID;
- project ID и agent ID;
- tariff ID;
- получатель;
- цена за сутки;
- количество суток = 1 по умолчанию;
- итоговая сумма = цена за сутки × число суток;
- срок действия счёта.

Пользователь меняет только число суток. Получатель, тариф и цена не должны быть свободно редактируемыми из deep link. До финального подтверждения кошелёк показывает полную расшифровку платежа.

## 3. Состояния платежа

`Draft → AwaitingUserConfirmation → Submitted → Confirming → Settled`

Альтернативные исходы: `Expired`, `Rejected`, `Underpaid`, `Refunded`, `Disputed`.

Только `Settled` в авторитетном ledger создаёт право на тариф. Повторные callbacks и повторная доставка события идемпотентны по invoice ID и transaction ID. Клиентский экран, возврат из кошелька или изображение чека не подтверждают оплату.

## 4. Адресное расширение

После `Settled` GLAFIRA Mother выпускает подписанный пакет, адресованный конкретной учётной записи и разрешённым устройствам. В него входят agent ID, тариф, capability IDs, голосовой preset, аватар, начало/конец срока, invoice reference, package version, hash, signature и правила отката. Не включать секреты и приватные ключи.

Клиент получает уведомление и кнопку «Обновить». После нажатия выполняется проверка подписи, хеша, получателя, версии, срока и совместимости. Декларативные конфигурации и контент предпочтительнее исполняемого кода. Исполняемые модули — только отдельный security review и явное разрешение владельца.

## 5. Доступ после установки

Core проверяет entitlement на серверной/доверенной стороне при каждом расширенном действии. Сам факт установки пакета не выдаёт бессрочное право. Время окончания фиксируется в UTC, отображается пользователю локально. При окончании срока расширенные capability выключаются, бесплатный уровень сохраняется, история чата и данные пользователя не удаляются.

## 6. Согласование с существующей Token архитектурой

Связанные направления: issue #107 (исследовательская база Token), #115 (кошелёк/ledger), #116 (распределённые вычисления и вознаграждения), #117 (VPN тарифы), #154 (GCU/GLF экономика). Не смешивать GCU измерение ресурсов с GLF расчётами и фактическим ledger. Тарифы агентов — отдельные SKU/capability entitlements, не автоматически глобальная подписка GLAFIRA.

## 7. Необходимые решения владельца до реализации

- единица расчёта и допустимые активы/валюты;
- цена суток для каждого тарифа;
- правила начала срока: после оплаты или после нажатия «Активировать»;
- максимальная длительность одного платежа;
- возвраты, отмены, споры, частичное исполнение и outage;
- комиссии сети и минимальная сумма;
- поддерживаемые кошельки и безопасный deeplink protocol;
- multi-device entitlement policy;
- правила offline grace и отзывов;
- налоговая, юридическая и потребительская проверка по странам.

До этих решений не выполнять платежи и не показывать тарифы как утверждённые.
