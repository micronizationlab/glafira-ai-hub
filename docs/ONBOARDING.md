# Онбординг участника GLAFIRA

## Перед началом работы

1. Прочитайте README.
2. Изучите инженерную передачу проекта (docs/GLAFIRA_COLLABORATOR_HANDOFF.md) и правила интеграции PR (docs/engineering/ELEVENTH_WORKSTREAM_PR_INTEGRATION.md).
3. Ознакомьтесь с приоритетами разработки (docs/IMPLEMENTATION_ROADMAP.md) и применимыми архитектурными контрактами.
4. Перед первой задачей обновите состояние main, issues, PR и CI. Снимки в документации не заменяют актуальные данные GitHub.
5. Новые помощники выполняют однократный стартовый анализ по инструкции handoff; рекомендации не дают права менять архитектуру или main.

## Настройка среды

- Android: Android Studio, JDK 17 и Gradle Wrapper из репозитория.
- Windows: .NET 8 SDK для соответствующих проектов.
- iOS: macOS и Xcode требуемой CI-версии.
- Клонируйте репозиторий и запускайте только нужные для задачи проверки.
- Локальные ключи и настройки размещайте в local.properties или системном хранилище; не добавляйте их в Git.

## Первая задача

1. Выберите issue, согласованную с текущими приоритетами и зависимостями.
2. Уточните критерии приёмки и владельца решения.
3. Создайте отдельную ветку от актуального main.
4. Реализуйте минимальный самостоятельный объём и тесты.
5. Откройте PR с заполненным шаблоном; укажите точные команды и результаты проверок.
6. Исправьте замечания; дождитесь документированного self-review Глафиры и успешных обязательных checks. Владелец сохраняет окончательное решение о слиянии.

## Правила

- Не коммитьте напрямую в main и не обходите защиту ветки.
- Не включайте секреты, персональные данные или реальные пользовательские данные в код и отчёты.
- Не объединяйте несколько несвязанных направлений в один PR.
- Не объявляйте функцию готовой только по документации или успешной сборке.
- Skipped проверки явно отмечайте как непроверенные.
